# Gangs → s2script SDK 0.27 / interop protocol 2 — Design

**Date:** 2026-10-07
**Status:** Implemented on `port/sdk-0.27` (offline-verified only; no live CS2 run)
**From:** `@s2script/sdk` 0.8 (protocol 1, `plugin(async (ctx) => …)` factory, async `@gangs/api` 0.1)
**To:** `@s2script/sdk` ^0.27.1 + `@s2script/cs2` ^0.19.2, `interfaceProtocol: 2`, `@gangs/api` **1.0.0**

## Why a redesign, not a mechanical port

Protocol 2 only carries **synchronous** methods: an implementation that returns a Promise is rejected
by `s2s build`'s producer-agreement check, and Promise/BigInt/any/unknown/functions are not wire
values. The 0.x service was async end to end — every manager call hit the database. Making the
service synchronous means the answers must already be in memory, so Gangs becomes a **cache-backed**
service with background persistence.

The SDK also removed the `plugin((ctx) => …)` factory from the public API. The plugin is now
`export function OnPluginStart()` plus named publics (`OnClientPutInServer`,
`OnClientPostAdminCheck`, `OnClientDisconnect`, `OnClientSayCommand`, `OnPluginEnd`), with
`publish`/`command` as load-window free functions.

## The contract change (0.x async → 1.0.0 sync)

`api.d.ts` is self-contained and is the package's `types` entry (the old `contract/gangs-api.d.ts`
vendored copy is gone). It exports `Contract { methods: GangsApi; forwards: {...} }` and matching
direct method exports.

| 0.x | 1.0.0 |
|---|---|
| namespaced object (`gangs.*`, `players.*`, `members.*`, `ranks.*`, `invites.*`, `stats.*`, `eco.*`, `perks.*`) | flat methods (`getGang`, `getMembers`, `hasPermission`, `getGangStat`, `tryPurchase`, `registerPerk`, …) |
| every method returns a Promise | every method is synchronous; `isReady()` + `OnReady` gate the initial load |
| `Gang { gangId, name }`, `GangPlayer` | `Gang { id, name }`, `Member { steamId, name, gangId, rank }` |
| descriptor-registered stats with record values | `StatValue = string \| number \| boolean \| null` (JSON text for structure) |
| snake_case events (`member_joined`, `player_credits_changed`, …) | PascalCase notifications (`OnMemberJoined`, `OnBalanceChanged`, …) |
| perks: fixed native set, `getCost`/`purchase` | native perks + `registerPerk(provider, spec)` (levelled or custom-command), `getPerkLevel`, `purchasePerk` |
| mutation API for gangs/members/ranks/invites | not exported — those are Gangs' own commands and menus |

This is a **major** break. Consumers must move to protocol 2, refresh the declaration
(`s2s add @gangs/api`), depend on `^1.0.0`, and remove every `await` on Gangs calls. Protocol 2 needs
host API 3; old API-2 hosts reject the new archive.

The contract file was used unchanged (it already passed the protocol-2 checker as a consumer copy;
the producer build and a scratch consumer build both pass).

## Architecture

```
plugin.ts ──► createGangs() ──► GangService (cache + mutations + forwards)
   │              ├─ Economy      (wallet / bank over the service's stats)
   │              ├─ PerkCatalog  (native + external perks)
   │              └─ buildGangsApi(...) → the published object
   ├─ publish("@gangs/api", api); service.setEmitter(handle.emit)
   ├─ command(...) × sm_gang_* (SDK-free handlers in commands/)
   └─ publics: client connect/disconnect, OnClientSayCommand (gang chat), OnPluginEnd
GangService ──► WriteQueue (one ordered promise chain) ──► GangsRepo (all SQL)
```

Everything under `service/`, `store/`, `eco/`, `perks/`, `api/`, `commands/`, `menus/menu-*` is
SDK-free and unit-tested with better-sqlite3; only `plugin.ts` and `menus/menus.ts` import the SDK.

### Cache and load

- **Boot** (`GangService.start`, the first queue op): `Database.open(db_connection)` → ensure tables →
  load every gang, rank, gang stat, every player with a gang, and those members' player stats. Then
  `ready = true` and `OnReady { gangs }` is emitted.
- **Connect** (`OnClientPutInServer` and `OnClientPostAdminCheck`, idempotent; plus every client
  already on the server at `OnPluginStart` for hot reloads): a gangless player's row is loaded — or
  inserted if missing — with their stats, as a queue op, so it observes every earlier write. A
  cached player just has their name refreshed (and persisted when it changed).
- **Disconnect**: a gangless player is evicted; members stay cached for the whole session.
- **Not ready**: reads return empty/null/0, writes return false (`-1` for the numeric economy
  writes), `purchasePerk` returns `not_ready`; commands reply "still loading".

### Writes

Every mutation updates the cache synchronously (so the next read, from any plugin, sees it) and then
enqueues its SQL on **one** `WriteQueue`: ops run strictly in order, one at a time; a rejected op is
logged with its label and the chain continues; nothing is thrown into the caller. Cached objects are
replaced, never mutated, so an enqueued write persists the value as of enqueue time. New gang ids are
`max(id)+1` from the cache, inserted with an explicit id (no `lastInsertId` round-trip). Disband
deletes the gang's ranks, gang stats and memberships in the same queued op, so a reused id never
inherits stale rows.

`OnPluginEnd` drains the queue and closes the database, best effort.

### Stats storage

The upstream per-stat instance tables are kept for Gangs' native stats (`gang_native_balance`,
`gang_native_capacity`, `gang_native_chat`, `gang_native_motd`, `gang_door_policy`, the
`gang_invitation` / `pending_invitation` records), so existing data stays readable. The public API
allows arbitrary stat ids (e.g. `perk:<id>`, not a valid SQL identifier), so every non-native id is
stored in one key/value table per scope (`<p>_gang_stat_values`, `<p>_player_stat_values`) as JSON
text, preserving its type. Public writes to native stats are type-checked against their column;
`gang_native_balance` is write-protected (use `grantGang`/`grantPlayer`, which emit
`OnBalanceChanged`); record stats read as JSON text and are not publicly writable.

### Economy

Wallet and bank are the upstream balance stat. `getBalance` includes the gang bank only for ranks
with `BANK_WITHDRAW`. `tryPurchase` draws bank-first, then wallet, and returns the remaining
balance or `-1` with nothing charged. Balances are clamped at zero (a deliberate change: 0.x allowed
negative wallets via `sm_credits`), which makes `-1` an unambiguous failure sentinel; the event's
`delta` is the applied change.

### Perks

Natives: **Capacity** (levels 0–14 = capacity 1–15, upstream cost curve; join refused at capacity),
**Gang Chat** (one level, 5000), **MOTD** (one level, 7500; text via `sm_gang_motd`).
`registerPerk(provider, spec)` adds an external perk: exactly one of `costs` (levelled; level stored
in gang stat `perk:<id>`) or `command` (custom; validated, no `;`/newlines). Re-registering from the
same provider replaces; another provider's id or a native id is refused. External perks are listed
only while `Plugins.list()` reports their provider `running`. `purchasePerk` order: `not_ready` →
`unknown_perk` (also for custom perks and stopped providers) → `not_in_gang` → `no_permission`
(PURCHASE_PERKS) → `max_level` → `insufficient_funds` (`tryPurchase`, bank first) → apply, emit
`OnPerkPurchased`. In the perks menu, choosing a custom perk runs its command as the player
(`client.fakeCommand`).

### Gang chat

`OnClientSayCommand` resolves eligibility synchronously from the cache (`.message`, member, gang owns
Gang Chat, rank holds `SEND_GANG_CHAT`): eligible messages go to online members and are suppressed
(`Handled`); **ineligible `.` messages now fall through as normal chat** (0.x had to swallow them
because eligibility was async).

### Forwards

Emitted after the cache reflects the change, payloads exactly as in the contract (optional fields
omitted, never `undefined`):
`OnReady` (boot), `OnGangCreated` + `OnMemberJoined(rank 0)` (create), `OnGangRenamed`,
`OnMemberJoined` (join), `OnMemberLeft` (`leave`/`kick`, and `disband` per member before
`OnGangDisbanded`), `OnMemberRankChanged` (promote/demote/transfer/rank deletion),
`OnPerkPurchased`, `OnBalanceChanged` (`kind: "player"` with `steamId`, or `"gang"` with `gangId`).

## Behaviour changes vs 0.x

- Gang names are unique (case-insensitive); `sm_gang_rename` (owner) added so `OnGangRenamed` has a
  source.
- `sm_credits` and economy writes need the target loaded (online or a gang member).
- Balances clamp at zero.
- The plugin id is now the package name `@gangs/api` (s2s derives it from `name`; the old
  `s2script.id: "gangs"` key is not read), so the generated config file name changes — operators
  must carry their config values over.
- Invites to offline players remain impossible (as before); an offline player's stale pending entry
  is ignored because a gang's own outgoing list is authoritative.

## Known limitations / unverified

- Not run on a live server: say-hook suppression, menus, `fakeCommand`, connect ordering, and
  whether `OnReady` emitted very early could precede the plugin becoming Active (consumers should
  also check `isReady()` when they attach, as the README example does).
- On unload/hot-reload, writes still queued when the context is torn down may be lost; the new
  instance reloads from the database.
- SQL dialect: SQLite-tested only. `ON CONFLICT … DO UPDATE` and backtick-quoted `` `Rank` `` are
  inherited from 0.x and are not portable to MySQL (upsert) / Postgres (backticks).
- No data migration of 0.x stats beyond reusing the same native tables (0.x only had native stats).
